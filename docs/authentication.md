# Authentication

The starter uses an organizer-approved team integration secret. The former
OAuth/PKCE login, callback, token storage and refresh implementation are removed.
No client ID, tenant, audience or callback registration is needed.

## Team setup

1. Ask Maximilian/the organizers to enable your named integration and share its
   one-time secret privately. Use the supplied API origin.
2. Run `npm run setup`, then set `VOICE_INTEGRATION_SECRET` in `.env`.
3. Keep the generated `STARTER_API_KEY` for clients calling **your starter**.
4. Run `npm start`. Open `http://localhost:3000`, enter the local key and registered
   test passenger phone, and check the connection.

Setup also runs automatically before start/dev/example:search. It migrates existing
`.env` files, removes obsolete `AUTH0_*` assignments and preserves other configured
values. Missing team access fails startup with an actionable configuration error;
there is no fallback to the old login. The secret is not generated by the starter:
it must be issued by the organizers.

## Request authentication

| Target | Bearer credential |
| --- | --- |
| Your starter `/api/...` | `STARTER_API_KEY` |
| mobie `/integrations/voice/...` | `VOICE_INTEGRATION_SECRET` |

The starter validates its local key and sends only the integration secret upstream.
Secrets stay server-side; they are never returned by an API or the manual test page.
Only `/`, `/page.js` and `/health` are public. Health means the process is running,
not that upstream team access or a passenger has been verified.

Caller/ride endpoints additionally require a trusted `X-Mobie-Call-Id` and
`X-Mobie-Caller-Phone`. For explicit phone-less browser tests, use
`X-Mobie-Call-Type: webCall` instead of a phone; the organizers must assign a web
test user to your integration. Invalid/unknown/ambiguous supplied phones never
fall back to that user. No caller identity is accepted from request body fields.

Call report uploads (`/vapi/events`, `/api/calls/...`) also use the local key
without caller headers. The starter adds the team secret when pushing logs to
`/integrations/voice-log/calls/...`; these routes grant no account actions.
See [call-logs.md](call-logs.md) for provider setup and the report schema.

Local geocoding needs only the starter key. Writes also need spoken consent
(`confirmed: true`) and a stable `Idempotency-Key`.

## Operation and troubleshooting

There is no passenger session to lose on restart, and calls can resolve different
registered accounts concurrently. Organizers can disable your integration or
rotate its secret; after rotation update `.env` and restart. A 401 from the starter
means its local key is missing/wrong. A 401 from mobie means team access must be
checked with the organizers. Caller 404 means no active matching passenger; 409
with `AMBIGUOUS_CALLER` means multiple accounts share the number.

For public deployments, use HTTPS, keep secrets out of URLs and run a trusted
provider adapter that takes identity from call metadata. There is no OTP or
independent caller-number ownership verification in this integration.
See [voice-integration.md](voice-integration.md) for full setup and request examples.
